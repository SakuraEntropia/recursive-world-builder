# 一轮递归的完整流程

```
1 载入 world.json
2 validate() —— 引用坏了先修
3 生成情景（同地点接触 / 边界 / 反事实）
4 逐条跑 critic
5 对每条缺口，往下问四层
6 停在「能解释多个现象」的那层
7 写提案（问题 / 根因 / 规则 / 影响 / 冲突 / 测试）
8 造反事实情景
9 等作者批准
10 批准后 apply()，再跑一遍测试
11 回到 3，直到触到停止条件
```

## 四层追问

| 层 | 问法 | 产出 |
|---|---|---|
| 1 | 这一件事缺什么后果 | 特例（不要） |
| 2 | 这一类事缺什么机制 | 规则（可以） |
| 3 | 这个机制依赖什么 | 依赖（更好） |
| 4 | 依赖的那层有没有定义 | 更底层缺口（最好） |

## 停止条件

**任何一条满足就停：**

- 轮数到顶
- 情景数到顶
- 提案数到顶
- 一轮没有新缺口
- **再挖只是在补细节，不是在补机制**
